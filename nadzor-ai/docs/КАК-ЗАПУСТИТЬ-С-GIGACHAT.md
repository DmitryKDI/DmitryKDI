# Как запустить комплексный анализ с GigaChat

Пошаговая инструкция для `RUN-VISION.bat` — единственного режима, который
реально обращается к ИИ и проверяет комплект **комплексно**: и текст, и
чертежи разом (Г.50). Свободный режим без ключа — `RUN-NO-LLM.bat`, см.
раздел «Что делает бесплатный прогон» ниже, чем он отличается.

## 1. Подготовка (один раз)

1. Установить WSL, если ещё не установлен: PowerShell от администратора →
   `wsl --install` → перезагрузка компьютера.
2. Запустить `RUN-VISION.bat` первый раз — он сам создаст рядом с собой
   папки `BEFORE`, `AFTER` и файл `vision-keys.env` (из шаблона) и
   остановится с сообщением «Ключ не заполнен».
3. Открыть `vision-keys.env` в Блокноте, вставить ключ в строку
   `GIGACHAT_CREDENTIALS=` (без пробелов и кавычек), сохранить файл.
   Ключ — то, что выдаёт личный кабинет GigaChat Studio при подключении
   (Client ID/Secret в одну Base64-строку либо готовый API-ключ проекта —
   смотреть в разделе «Подключение GigaChat в свой проект»).

## 2. Каждый прогон

1. Положить проектную документацию (ПД) в папку `BEFORE`.
2. Положить рабочую/исполнительную документацию (РД/ИД) в папку `AFTER`.
3. Запустить `RUN-VISION.bat`. Окно ничего не спрашивает дальше — само
   обновляет копию репозитория внутри WSL, ставит зависимости при первом
   разе и запускает анализ.
4. Дождаться надписи «Готово». Прогон обращается к внешнему провайдеру и
   не мгновенный — от минуты до нескольких минут, зависит от объёма
   документации и числа найденных кандидатов.

## 3. Что именно проверяется за один прогон (Г.50)

`RUN-VISION.bat` теперь запускает единую цепочку `--kind all
--verify-requirements`, а не только требования, как раньше:

| Блок | Что делает | Нужен ли ключ |
|---|---|---|
| Кросс-проверка помещений/оборудования | Реестры ПД↔РД целиком, с причиной расхождения (не просто «есть/нет») | нет |
| Сводка требований ПД (форма 1+2) | Список требований с кодом системы и без — из прозы пояснительной записки | ключ ускоряет извлечение (общий ИИ-путь вместо узкого regex) |
| Сверка требований с РД | Код — текстовый поиск; требование без кода — эскалация в зрение по листу РД | зрение требует ключ |
| Общий каталог требований (форма 3) | Более широкий охват — требования без привязки к помещению (материалы, ГОСТ, безопасность) | нет для каталога и токен-сверки; ключ — для семантической сверки по смыслу |
| **Граф маршрутизации (чертежи)** | Сравнивает, куда ведёт трасса от каждого помещения на плане РД против ПД — расхождение, которое НЕ видно по одному лишь тексту/реестру | нет (чистая геометрия), но включается автоматически ТОЛЬКО если задан ключ (см. ниже) |
| Триангуляция + очередь эскалации | Сводит все источники — находка подтверждена, если её независимо увидели ≥2 источника; иначе — очередь с конкретным вопросом человеку | нет |

**Важно про чертежи:** без явного списка номеров помещений граф
маршрутизации раньше не запускался вообще. Теперь при наличии ключа он
включается автоматически — берутся помещения, которые уже показали
расхождение в реестре (до 15 штук за прогон, `MAX_AUTO_ROUTING_ROOMS` в
`scripts/registry_diff.py`) — не весь комплект, потому что каждое
помещение стоит времени на обработку чертежа (~6 секунд на лист). Если
нужно проверить конкретные, заведомо интересные номера явно — можно
запустить вручную внутри WSL:
```
python3 scripts/registry_diff.py --before ПД.pdf --after РД.pdf \
  --kind routing --rooms 012,140,142
```

## 4. Где смотреть результат

Файл `requirements_summary.txt` рядом с папками `BEFORE`/`AFTER` —
пишется по мере готовности (Г.41), можно открывать и во время работы
прогона, не только после «Готово». Внутри по порядку: сводка требований,
общий каталог, сверка требований с РД (текст и токен), семантическая
сверка по смыслу, граф маршрутизации, итоговая триангуляция и очередь
эскалации.

Читать очередь эскалации так: у каждого пункта — какие источники его уже
подтвердили и каких не хватает. Один источник — повод присмотреться, не
готовый вердикт (см. `## Г.46`/`## Г.30 п.4` в `CLAUDE.md`).

## 5. Частые проблемы

**«Ключ не заполнен»** — `vision-keys.env` не отредактирован, см. шаг 1.3.

**Обрыв по TLS / SSL-ошибка при обращении к GigaChat** — на части машин
без доверенного набора сертификатов НУЦ Минцифры в системе может
понадобиться `GIGACHAT_CA_BUNDLE=false` в `vision-keys.env` (та же
переменная, что и `.env` приложения) — не убирает проверку сертификата
совсем, а переключает её на встроенный набор Python вместо системного.

**`WSL (N - Relay) ERROR: CreateProcessCommon:818: execvpe(bash) failed`**
во время работы `.bat` — если при этом сам прогон всё равно доходит до
«Готово» (как в норме), это НЕ ошибка самого скрипта: `RUN-VISION.bat`
вызывает WSL явно (`wsl -e bash -c "..."`) и получает результат. Строки
вида «WSL (9 - Relay)» — отдельные фоновые попытки других программ
(например, вкладок терминала, VS Code Remote-WSL или уже закрытых окон)
поднять свою WSL-сессию, не связанные с этим `.bat`. Если раздражают —
`wsl --shutdown` в PowerShell (закрывает все WSL-сессии, следующий запуск
`.bat` поднимет новую сама) и `wsl --list --verbose` (проверить, что
default-дистрибутив стоит и запущен). Если сам прогон НЕ доходит до
«Готово» и падает именно на команде `.bat` — это другая, реальная
проблема окружения WSL, тогда стоит прислать полный текст ошибки.

**Пустой/маленький `requirements_summary.txt`** — проверить, что в
`BEFORE`/`AFTER` вообще лежат `.pdf` (не `.docx`/сканы в других
форматах) — скрипт остановится с понятной ошибкой раньше, если папка
пуста.

## 6. Что делает бесплатный прогон (`RUN-NO-LLM.bat`) — для сравнения

Тот же `--kind all`, но без ключа: реестры помещений/оборудования, форма
1/2/3 требований по узкому regex-пути (без ключа общий ИИ-путь
недоступен), сверка по коду/токену. Не включает: эскалацию в зрение,
семантическую сверку по смыслу, граф маршрутизации (без ключа автовыбор
помещений для него не срабатывает — см. таблицу выше). Хорош как быстрая
бесплатная проверка перед тем, как тратить время/деньги на полный
прогон с ключом.
