# Архитектура

## 1. Топология фазы 1

Модульный монолит с жёсткими границами пакетов. Границы соответствуют будущим
сервисам: извлечение любого модуля не требует изменения бизнес-логики.

Границы проверяются автоматически: `import-linter` выполняет пять контрактов на
каждом коммите, нарушение останавливает сборку.

## 2. Контекст (C4, уровень 1)

```
        ┌──────────────┐         ┌──────────────────┐
        │  Инспектор   │         │ Начальник отдела │
        └──────┬───────┘         └────────┬─────────┘
               │ браузер, планшет на объекте        │
               ▼                                    ▼
        ┌──────────────────────────────────────────────────┐
        │            НАДЗОР.ИИ (модуль экосистемы)         │
        └───┬───────────┬──────────────┬───────────────┬───┘
            │           │              │               │
            ▼           ▼              ▼               ▼
      ┌─────────┐ ┌──────────┐  ┌─────────────┐ ┌────────────┐
      │  СУДИР  │ │ИАИС ОГД  │  │Языковые     │ │АИС         │
      │личность │ │сведения  │  │модели       │ │«Стройнадзор»│
      │и права  │ │об объекте│  │(суверенные) │ │акты и      │
      └─────────┘ └──────────┘  └─────────────┘ │предписания │
                                                └────────────┘
```

Разделение контуров принципиально: из СУДИР приходит **личность и полномочия**,
из ИАИС ОГД — **сведения об объекте**. Смешивать их нельзя.

## 3. Контейнеры (C4, уровень 2)

| Контейнер | Технология | Ответственность |
|---|---|---|
| Интерфейс | React 18, TypeScript, Vite, PWA | Экраны, офлайн-режим на объекте, печать карты внимания |
| Приложение | Python 3.12, FastAPI | Маршруты, разграничение доступа, оркестрация анализа |
| Обработчик | тот же образ, отдельный процесс | Тяжёлые файлы с ограничением памяти и времени |
| Хранилище | PostgreSQL 16 (+pgvector в фазе 2) | Объекты, документы, находки, оценки, журнал аудита |
| Файловое хранилище | S3-совместимое | Неизменяемые оригиналы, доступ по подписанным ссылкам |

## 4. Компоненты (C4, уровень 3)

```
packages/
├── llm_core/      порт LLMProvider, роутер, недоверенный контейнер, детектор инъекций
├── documents/     приём по сигнатуре, разбор PDF, штамп, факты с source_ref
├── norms/         пункты нормативов, поиск, контроль актуальности редакций
├── analysis/      состояния и переходы, правила, LLM-слой, diff, скоринг,
│                  карта внимания, формирование документов
├── integrations/  СУДИР, ИАИС ОГД, каталог прочих систем
├── audit/         журнал с цепочкой хэшей, происхождение выводов
└── api/           маршруты, разграничение доступа, схема хранения
```

Направление зависимостей: `api → analysis → {documents, norms, integrations, audit} → llm_core`.
Обратных зависимостей нет.

## 5. Ключевое решение: один движок, семь переходов

Сравниваются не «проект с проектом», а любые два состояния жизненного цикла.
`analysis.transitions.analyze` принимает тип перехода и два комплекта, возвращает
список находок. Тип перехода выбирает набор правил из словаря `RULE_REGISTRY`,
но не меняет архитектуру. Добавление восьмого перехода — строка в словаре.

## 6. Порты и адаптеры

Интерфейс создаётся только там, где есть две реализации по факту:

| Порт | Реализации | Обоснование |
|---|---|---|
| `LLMProvider` | GigaChat, YandexGPT, локальный vLLM, Claude, заглушка | Требование импортозамещения |
| `IdentityProvider` | СУДИР (OIDC), мок | Разработка без доступа к продуктивному контуру |
| `UrbanDataProvider` | ИАИС ОГД, мок | То же |
| `DiffEngine` | растровый, DXF | Разные форматы графики |

Всё остальное — прямые функции. `TransitionAnalyzer` реализован функцией,
`scoring` — одной функцией с конфигурируемыми весами, а не пакетом.

## 7. Извлечение модуля в отдельный сервис

Каждый пакет общается через публичные функции и схемы Pydantic. Для выделения,
например, `documents` в самостоятельный сервис достаточно заменить прямые вызовы
на HTTP-клиент с тем же контрактом: бизнес-логика `analysis` не меняется, потому
что она работает с моделями `ParsedDoc` и `Fact`, а не с реализацией разбора.

## 8. Что сознательно не сделано в фазе 1

Векторный поиск по нормативам выполняется в памяти процесса, а не в pgvector:
объём нормативного пакета демонстрационного контура этого не требует. Контракт
функции `norms.search` при переносе не меняется. Остальные перенесённые работы
перечислены в `roadmap.md` с оценкой трудозатрат.
