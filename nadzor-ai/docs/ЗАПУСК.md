# Как запустить и что нажимать

## Модель ИИ — только локальная

Облачных провайдеров, ключей и сертификатов у решения нет: модель работает
внутри контура, документы никуда не передаются. Официальный запуск — docker
compose с сервисом модели на GPU, см. README, раздел «Официальный запуск».

Для разработки на своей машине достаточно любого Chat Completions-совместимого сервера
модели внутри сети (адрес — loopback или частная сеть) и двух переменных в
`nadzor-ai/.env`:

```
NADZOR_LOCAL_LLM_URL=http://127.0.0.1:8000
NADZOR_LOCAL_LLM_MODEL=Qwen/Qwen2.5-VL-7B-Instruct
```

Адрес вне контура программа отвергнет сама — это не ошибка настройки, а
защита: внешние сервисы в зачётном прогоне запрещены.

## Запуск

```bash
cd nadzor-ai
./scripts/start-all.sh          # Linux / WSL
```

Скрипт сам ставит зависимости, освобождает порты и поднимает два процесса:

| Порт | Что |
|---|---|
| 8010 | движок разбора документов (FastAPI) |
| 5173 | интерфейс (Vite, проксирует на 8010) |

Открыть: **http://localhost:5173**. Остановить — Ctrl+C в том же окне.

## Вход

Интерфейс открывается экраном входа: логин и пароль (ТЗ 12). Первый
администратор создаётся при первом запуске.

- Пароль задан заранее — в `.env` рядом с `docker-compose.yml`:
  `NADZOR_ADMIN_LOGIN=admin` и `NADZOR_ADMIN_PASSWORD=<пароль от 8 символов>`.
  Задать нужно ДО первого запуска: когда пользователи уже есть, переменные
  больше не читаются.
- Пароль не задан — он создаётся случайным и записывается в файл, посмотреть:
  `docker compose exec backend cat /app/state/initial-admin-password.txt`
  (первая строка — логин, вторая — пароль).

Учётные записи для проверяющих заводит администратор: «Администрирование» →
«Пользователи» → логин, ФИО, пароль и роль (инспектор, супервизор,
ML-инженер). Роль определяет, какие экраны и действия доступны.

## Что нажимать

Экран один — «Проверка ПД → РД → ИД».

1. **Загрузите тома** в зону загрузки (PDF, DOCX или XML) и заполните карточку
   каждого: объект, стадия (ПД/РД/ИД), шифр, редакция, статус утверждения,
   предшественник. Сканы распознаются сами.
2. **Выберите объект и документы** в блоке «Комплект для проверки» и
   запустите проверку. Ход виден по этапам; проверку можно остановить.
3. **Разберите протокол**: у каждого кандидата — ожидаемое и полученное
   значение, доказательства на листах ПД, РД и ИД с подсветкой области.
   Решение: подтвердить, не подтвердить (с причиной), оставить кандидатом
   или запросить уточнение.
4. **«Завершить»** — когда решены все кандидаты. После этого протокол
   выгружается в PDF, DOCX, XML или JSON, а изменения закрыты.

Модель проверяется до запуска: если она не загружена или не отвечает,
параметры получают «не выполнялось» с причиной, а не «нарушений нет».

## Хранилище

Оригиналы лежат в отдельной базе по отпечатку содержимого — одинаковые файлы
хранятся один раз. Каталог загрузок — только кэш: удаляется в любой момент,
файлы восстановятся из базы. Документ, входящий в сохранённый протокол,
удалить нельзя.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| «локальная модель не отвечает» | сервис модели не запущен или веса ещё грузятся: `docker compose ps` |
| «локальная модель не задана» | задайте `NADZOR_LOCAL_LLM_MODEL` и `NADZOR_LOCAL_LLM_URL` |
| порт занят | закройте прошлый запуск: `pkill -f 'uvicorn app.main:app'` |
| «файл больше допустимого» | через `/api/v1` — 50 МБ на файл и 200 МБ на пакет |
| проверка идёт долго | комплект в сотни листов — это десятки вызовов модели; ход виден по этапам |
