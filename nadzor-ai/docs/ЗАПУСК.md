# Как запустить и что нажимать

## Модель ИИ — только локальная

Облачных провайдеров, ключей и сертификатов у решения нет: модель работает
внутри контура, документы никуда не передаются. Официальный запуск — docker
compose с сервисом модели на GPU, см. README, раздел «Официальный запуск».

Для разработки на своей машине достаточно любого Chat Completions-совместимого сервера
модели внутри сети (адрес — loopback или частная сеть) и двух переменных в
`nadzor-ai/.env`:

```
NADZOR_LOCAL_LLM_URL=http://127.0.0.1:8000
NADZOR_LOCAL_LLM_MODEL=Qwen/Qwen2.5-VL-7B-Instruct
```

Адрес вне контура программа отвергнет сама — это не ошибка настройки, а
защита: внешние сервисы в зачётном прогоне запрещены.

## Запуск

```bash
cd nadzor-ai
./scripts/start-all.sh          # Linux / WSL
```

Windows — `START-NADZOR.bat` (тот же скрипт через WSL).

Скрипт сам ставит зависимости, освобождает порты и поднимает два процесса:

| Порт | Что |
|---|---|
| 8010 | движок разбора документов (FastAPI) |
| 5173 | интерфейс (Vite, проксирует на 8010) |

Открыть: **http://localhost:5173**. Остановить — Ctrl+C в том же окне.

## Что нажимать

1. **Загрузите документы** в две зоны: «Проектная документация» и «Рабочая /
   исполнительная». Раздел тома определяется сам; если ошибся — исправьте
   вручную, ручной выбор побеждает автоматику.
2. **«Разобрать»** в карточке 1 (ПД). Состав тома считается всегда, даже без
   связи с моделью; требования — только при рабочей связи.
3. **«Разобрать»** в карточке 2 (РД) — то же самое для рабочей документации.
   Если связного текста в ней нет (обычное дело), покажется состав тома.
4. **«Сверить»** в карточке 3 — соответствие РД требованиям ПД. Результат:
   подтверждено / требует проверки (с листами) / не проверялось.

Связь с моделью проверяется **до** разбора: при обрыве прогон остановится с
явной причиной, а не выдаст пустую сводку за результат.

## Хранилище

Оригиналы лежат в отдельной базе `data/file_store.db` — одинаковые файлы
хранятся один раз. Каталог `packages/backend/uploads/` — только кэш,
удаляется в любой момент, файлы восстановятся из базы.

Карточка «Хранилище документов» в интерфейсе показывает занятое место и даёт
две кнопки: убрать по сроку хранения и освободить кэш. Оригинал, на который
ссылается загруженный документ, не удаляется никогда.

Лимиты и срок хранения — там же в настройках: размер файла, число страниц,
вес одной части (тяжёлый том режется на части, нумерация листов остаётся
исходной), срок хранения в днях.

## Репозиторий приватный — вход в GitHub

После того как репозиторий сделали приватным, `git` при обновлении просит
логин. Пароль от аккаунта GitHub не принимает с 2021 года — нужен либо
токен, либо вход через браузер.

**Важно: логин Windows и логин внутри WSL — разные хранилища.** Проект
обновляется из WSL, поэтому вход, выполненный в обычном окне `cmd`, git-у
в WSL не виден: обновление молча не приезжает, а на экране остаётся старая
версия. `START-NADZOR.bat` сам подключает WSL к менеджеру учётных данных
Git for Windows, но на компьютере, где батник ещё старый, это делается
один раз вручную:

```bash
wsl
git config --global credential.helper \
  "/mnt/c/Program Files/Git/mingw64/bin/git-credential-manager.exe"
cd ~/nadzor-project && git fetch origin claude/new-session-d44es2
```

Откроется окно входа GitHub — войдите, и доступ запомнится. Дальше всё
работает само. Если файла по этому пути нет, поищите
`git-credential-manager.exe` в `C:\Program Files\Git\mingw64\libexec\git-core\`.

**Токеном.** github.com → Settings → Developer settings → Personal access
tokens → Tokens (classic) → Generate new token, право `repo`. При запросе
пароля вставьте токен вместо пароля.

Запуск при этом **не блокируется**: если доступа нет, окно скажет
«Update skipped» и поднимет систему той версией, что уже на диске.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| «локальная модель не отвечает» | сервис модели не запущен или веса ещё грузятся: `docker compose ps` |
| «локальная модель не задана» | задайте `NADZOR_LOCAL_LLM_MODEL` и `NADZOR_LOCAL_LLM_URL` |
| порт занят | закройте прошлый запуск: `pkill -f 'uvicorn app.main:app'` |
| «файл больше допустимого» | лимит в настройках, по умолчанию 512 МБ |
| разбор идёт долго | том в сотни листов — это десятки вызовов модели; прогресс виден в карточке |
