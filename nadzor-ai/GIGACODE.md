# GIGACODE.md — инструкции для GigaCode в этом проекте

Ты работаешь внутри `nadzor-ai/` — сервис предиктивного строительного
надзора. Здесь же, параллельно с тобой, работает Claude Code (в облачной
сессии и в CLI) — вы делите одну и ту же ветку `claude/new-session-d44es2`.
Перед любой правкой прочитай `CLAUDE.md` в этой же папке целиком — это
основной проектный документ с историей решений (записи Г.1–Г.78+), и все
правила ниже — короткая выжимка из него для твоей роли, не замена.

**Первым делом в КАЖДОЙ сессии — прочитай `CURRENT-TASK.md` рядом с этим
файлом.** Там актуальная задача на сейчас (что именно прогонять, в каком
формате нужен результат) — пользователь обновляет её через Claude Code
вместо того, чтобы присылать тебе новый промт в чат каждый раз. Если
`CURRENT-TASK.md` расходится с тем, что просит пользователь в чате прямо
сейчас — слушай чат, он важнее (файл может отставать на несколько минут
от разговора), но по умолчанию, без свежих указаний, действуй по нему.

## Твоя роль здесь — диагностика, не редактура

У тебя есть то, чего нет у облачной сессии Claude Code: реальный ключ
GigaChat и реальные документы пользователя на диске. Твоя основная
ценность — **прогонять механизм на реальных данных и честно докладывать
результат**, а не переписывать код. Если пользователь прямо не попросил
код — не редактируй `packages/`, `scripts/`, `frontend/`: опиши находку
(файл, строка, что не так, чем подтверждено — реальный вызов, не
предположение), Claude Code внесёт фикс с тестом в своей сессии. Так не
возникает двух источников правок в одной ветке одновременно.

## Три обязательных правила (Г.10 / Г.11 / Г.12 из CLAUDE.md)

1. **Тишина никогда не значит «всё чисто».** Сорванный вызов, пустой
   результат, непроверенный раздел — пиши явно, не пропускай молча.
2. **Никогда не угадывай.** Не знаешь, что вернул реальный вызов —
   смотри реальный вывод, не описывай ожидаемое поведение как факт.
3. **Не коммить и не пуш ничего с реальными данными объекта** — номера
   помещений, тексты найденных нарушений, содержимое реальных PDF/имена
   реальных файлов. Находки по конкретному объекту — только в текстовый
   отчёт пользователю (файл вне репозитория или в чат), никогда в git.
   Если нужен пример для теста — только синтетика/обезличенный текст
   (см. `data/known_violations.json` и как он пополняется — тот же
   принцип: обезличенно, с другого объекта, не с текущего).

## Архитектура — где что искать (не путать два движка)

- `packages/api/` + `packages/analysis/` + `packages/llm_core/` — СТАРЫЙ
  движок: CRM-оболочка, RBAC, аудит-цепочка, демо-данные. Провайдеры ЛЛМ
  здесь настраиваются отдельно, через `config/providers.yaml` (там же
  своя политика суверенности провайдеров — не трогать без прямого
  запроса пользователя).
- `packages/backend/` (порт 8010, `app.main:app`) — РЕАЛЬНЫЙ движок
  сравнения документов, вся практическая механика Приложения Г
  (`app/triangulation.py`, `app/escalation.py`, `app/routing_diff.py`,
  `app/requirement_llm_filter.py`, `app/ventilation_mo.py` и т.д.).
  `app/llm.py` — ровно два провайдера: `anthropic` и `gigachat` (Г.71) —
  не добавляй других без прямого запроса.
- CLI-вход в реальный движок — `scripts/registry_diff.py` (флаг
  `--kind all` — вся цепочка разом, см. `--help` за полным списком) и
  `scripts/scan_cli.py`. HTTP-вход — частичный: `POST/GET
  /triangulated-runs` в `packages/backend/app/main.py` (через
  `app/triangulated_pipeline.py`) — это НЕ полное зеркало
  `run_triangulated()` из CLI, часть блоков туда ещё не перенесена
  (проверяй импорты `triangulated_pipeline.py`, не угадывай по названию).
- Запуск: `START-NADZOR.bat` (WSL, обновляет репозиторий сам) или
  `scripts/start-all.sh` напрямую. `RUN-NO-LLM.bat` — прогон без ключа,
  `RUN-VISION.bat` — комплексный прогон с ключом GigaChat (папки
  `BEFORE`/`AFTER` рядом с .bat-файлами). Подробно — `docs/КАК-ЗАПУСТИТЬ-С-GIGACHAT.md`.

## Провайдер ЛЛМ

`packages/backend` поддерживает только `anthropic` и `gigachat` (Г.71) —
Ollama/OpenAI/Google/YandexGPT из него убраны полностью, попытка задать
`provider="local"` или любой другой даст `ValueError`. Не предлагай их
вернуть без прямого запроса пользователя.

перезаписывай их молча, спроси пользователя.
