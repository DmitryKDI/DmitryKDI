## 0. Жёсткие правила

1. **ТЗ — первично.** Перед правкой найти пункт ТЗ, который она выполняет.
   Нет такого пункта — правку не делать, а спросить пользователя.
2. **Закрытый контур.** Модель только локальная (vLLM на GPU стенда), OCR —
   Tesseract в образе, внешних API и облачных провайдеров нет. Обращение к
   адресу вне контура отклоняется кодом до отправки запроса.
3. **Каждый вывод — с доказательством.** Кандидат ссылается на файл, SHA-256,
   стадию, шифр, редакцию, лист и координаты (bbox в долях видимого листа)
   в сравниваемых стадиях. Вывод без источника — дефект, закрытый тестом.
4. **Техническая ошибка ≠ «нарушений нет».** Недоступная модель, нечитаемая
   страница, пропущенный лист — видимое состояние с причиной
   (`not_run`, `MISSING_EVIDENCE`, `CLARIFICATION_REQUIRED`, `ERROR`).
5. **Решение — за инспектором.** `CONFIRMED_VIOLATION` ставит только
   инспектор; система формирует кандидатов и гипотезы.
6. **Код общий для любой документации.** Пример, на котором идёт работа, не
   попадает ни в код, ни в комментарии, ни в промпты, ни в эту инструкцию.
   Наблюдение о конкретном разделе — данные реестра со статусом n=1/n=0, а
   не строчка механики. Реквизиты проверяемых объектов (шифр, организация,
   маркировка тома, текст) в репозиторий не идут вообще. Явная пометка
   границы («статус n=1», «на втором комплекте не проверено») разрешена и
   обязательна. Проверка — `make check-generic`.
7. **Числовые константы объявлены.** Новая константа ML-модулей заносится в
   `packages/ml/tests/test_constants_are_declared.py` одним из видов:
   БЮДЖЕТ, ПРАВИЛО ЯЗЫКА, ГЕОМЕТРИЯ/ФОРМАТ, ПОДОГНАНО с честным `n=`.
   Не отсеивать там, где можно ранжировать; отрицательный результат
   измерения записывать как результат, а не прятать за «средним» числом.
   Контрольный вопрос: «если положить сюда сто томов, правка сработает без
   подстройки?»
8. **Секреты и данные объектов — не в git.** Ключи, токены, пароли — только
   в `secrets/` и `.env` стенда (`scripts/make-secrets.sh`). Тесты строят
   свои документы в памяти.
9. **Язык.** Комментарии и документация — на русском; код и имена — на
   английском. Писать так, будто код читают на аудите безопасности.
10. **Коммиты** — `type: описание` (feat, fix, refactor, docs, test, chore,
    perf, ci), без строк соавторства ИИ.

## 1. Что делает сервис (ТЗ 1.2)

- выявляет несоответствия между ПД, РД и ИД по **132 параметрам** Матрицы
  контроля (`data/parameter_catalog_v1_1.json` → таблица `params`);
- даёт инспектору верифицировать кандидатов с фиксацией решения и основания;
- обменивается данными с внешними ИС по API (целевая — ИАИС «РиН»);
- контролирует наличие документов и принимает дозагрузку до финализации.

Взаимодействие — REST over HTTPS (JSON), схема OpenAPI 3.0 с обязательной
валидацией (ТЗ 1.3). Принцип — асинхронная pull-модель: загрузка возвращает
`process_id`, статус и результат запрашиваются отдельно (ТЗ 1.4).

## 2. Архитектура (ТЗ 1.5)

| Часть по ТЗ | Где | Что внутри |
|---|---|---|
| Клиент — React | `frontend/` | вход, дашборд, проверка ПД → РД → ИД, дообучение, администрирование |
| Сервер — Node.js | `packages/server/` | Fastify + TypeScript; REST `/api/v1` (схемы маршрутов = OpenAPI 3.0.3), SQLCipher-база, хранилище оригиналов AES-256-GCM, аудит, РиН, фоновые задачи |
| ML-модули — Python ≥ 3.11 | `packages/ml/` | воркер очереди (разбор, OCR, CV, проверка по матрице, свободный поиск) и внутренний REST |
| Очередь — RabbitMQ | `packages/server/src/queue/contracts.ts` ↔ `packages/ml/app/contracts.py` | `inspector.parse`, `inspector.inspect`, `inspector.results`, `inspector.progress` |
| Кэш — Redis (ТЗ 9.1, п.5) | `packages/ml/app/kv.py` | разбор по хешу файла и ответы модели, зашифрованы; флаг остановки проверки |
| Модель | `docker-compose.yml`, сервис `llm` | vLLM + Qwen2.5-VL-7B-Instruct, CUDA runtime в образе |

Долгие операции (разбор тома, проверка комплекта) идут через очередь;
короткие (изображение листа, связь с моделью, метрики, проверка правила) —
через внутренний REST ML-модулей. Контракт очереди меняется одновременно в
обоих файлах контракта; расхождение ловит тест.

## 3. Внешний контракт

| Что | Значения |
|---|---|
| Статус процесса | `PENDING` → `PARSING` → `READY` → `VERIFYING` → `COMPLETED` → `FINALIZED` (+ `ERROR`, `CANCELLED`) |
| Статус загрузки | `PD/RD/ID_UPLOADED`, `_PARTIAL`, `_MISSING` |
| Сценарий | `FULL`, `PD_RD_ONLY`, `PD_ID_ONLY`, `RD_ID_ONLY`, `SINGLE_ONLY`, `PARTIALLY_LOADED` |
| Полнота | `COMPLETE`, `MISSING_EVIDENCE`, `NOT_APPLICABLE`, `NOT_COMPARABLE`, `CLARIFICATION_REQUIRED` |
| Находка | `CANDIDATE`, `NEGATIVE_VERIFIED`, `CONFIRMED_VIOLATION` (только инспектор), `SUSPICION` |

В ответе о процессе `status` — словарь ТЗ, `run_state` — внутреннее
состояние задачи (`queued`, `parsing`, `running`, `completed`, `cancelled`,
`error`). Протокол: статус загрузки, сценарий, пять таблиц (комплектность,
кандидаты, подтверждённые, проверенные отрицательные, гипотезы), карточки
доказательств, версии матрицы, модели, набора данных и `input_manifest_hash`.
Выгрузка — JSON, XML, DOCX, PDF (и CSV таблицы проверок).

## 5. Безопасность, эксплуатация, приёмка

- **ТЗ 12:** вход по логину и паролю (scrypt), роли, cookie HttpOnly;
  TLS 1.3 (nginx, порт 5443); база SQLCipher и хранилище AES-256-GCM, кэш
  ML в Redis зашифрован; антивирус ClamAV до сохранения файла;
  резервные копии и проверка целостности. Модель угроз —
  `docs/threat-model.md`.
- **ТЗ 13:** JSON-логи (timestamp, level, service, message, request_id,
  user_id), ротация 90 / 365 дней; Prometheus, Grafana, Alertmanager (почта
  и Telegram), ELK — профили `monitoring` и `logging` в `docker-compose.yml`.
- **ТЗ 14:** метрики по эталону — `POST /api/v1/ml/evaluate`, порядок —
  `docs/ПРИЁМКА.md`.

## 6. Стенд проверки (сведения организаторов)

1× H100 80 ГБ на команду (GPU может быть общим для нескольких команд),
24 ядра / 48 потоков, до 640 ГБ ОЗУ, от 300 ГБ диска. GPU передаётся через
NVIDIA Container Toolkit; драйвера NVIDIA в образе нет, CUDA runtime — в
образе vLLM. Подключение к собственному публичному API команды запрещено —
всё работает внутри контура. Работа на CPU не обязательна, нормативы
проверяются на GPU. Настройки под стенд — `docs/ЗАПУСК.md`.

## 7. Как работать

```bash
make install          # зависимости сервера, ML-модулей и интерфейса
make test             # тесты сервера (vitest) и ML-модулей (pytest)
make check-generic    # код общий, константы объявлены
make lint             # ruff (ML) и tsc (сервер)
make openapi          # docs/openapi.json из схем маршрутов сервера
```

Порядок правки: пункт ТЗ → тест → код → `make test` и `make check-generic`
→ обновить документацию, если изменился контракт или запуск.
