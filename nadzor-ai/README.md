# НАДЗОР.ИИ

Модуль предиктивного строительного надзора для цифровой экосистемы стройкомплекса
Москвы. Задача города № 10, Комитет государственного строительного надзора
города Москвы.

[![Проверки безопасности](https://github.com/DmitryKDI/DmitryKDI/actions/workflows/security.yml/badge.svg)](../../actions/workflows/security.yml)

## Что делает

Инспектор загружает комплект документации и получает ответ на один вопрос:
**на что смотреть в первую очередь и почему**.

Система сравнивает не «проект с проектом», а любые два состояния жизненного
цикла объекта. Один движок, семь переходов:

| Переход | Что ищем |
|---|---|
| T1 | ПД ред. N → ПД ред. N+1: изменения, требующие повторной экспертизы |
| T2 | ПД → заключение экспертизы: учтены ли замечания |
| T3 | ПД → РД: отступления рабочей документации от проектных решений |
| T4 | РД ред. N → РД ред. N+1: изменения в производстве работ |
| T5 | РД → ИД: соответствие фактически выполненного проекту |
| T6 | ИД → ИД: внутренняя непротиворечивость комплекта |
| T7 | Состояние → нормативная база: соответствие СП, ГОСТ, техрегламентам |

Каждый вывод содержит **ссылку на пункт норматива** и **координаты области на
листе документа**. Вывод без источника не сохраняется и не показывается.

## Запуск

### На обычном компьютере, без Docker

```bash
./scripts/start-all.sh
```

Скрипт сам доставит недостающее, сформирует демонстрационный комплект и
поднимет всё, что нужно. Оба сервера работают на файловой базе SQLite, поэтому
ни Docker, ни PostgreSQL не требуются. Когда в окне появится «Всё работает» —
открывайте http://localhost:5173.

На Windows то же самое делает `START-NADZOR.bat`: он же скачивает и обновляет
проект, так что достаточно одного этого файла на рабочем столе.

Поднимаются три процесса:

| Порт | Что это |
|---|---|
| 5173 | интерфейс, проксирует оба сервера |
| 8000 | основной сервер: объекты, гипотезы, журналы, аудит, RBAC |
| 8010 | сравнение загруженных документов (Anthropic/GigaChat) |

Ключ провайдера (Anthropic или GigaChat) настраивается прямо в интерфейсе —
«Новый анализ» → «Настроить ИИ». Без ключа работают все экраны, кроме
запуска сравнения.

### В контейнерах

```bash
docker compose up --build
```

Интерфейс — http://localhost:5173, программный интерфейс и его описание —
http://localhost:8000/docs.

### Отдельные шаги для разработки

```bash
make install      # зависимости
make data         # демонстрационный комплект: 45 документов по 3 объектам
make api          # сервер на порту 8000
make web          # интерфейс на порту 5173
```

## Сценарий демонстрации

1. Вход через мок СУДИР — выбор роли в один клик. Один и тот же объект
   выглядит по-разному для инспектора, начальника отдела и аудитора.
2. Новый анализ: номер разрешения `77-123456-012345-2024` → карточка объекта
   заполняется из ИАИС ОГД → выбор переходов → честный прогресс по этапам.
3. Журнал гипотез: 16 находок по основному объекту, фильтры, выгрузка выборки.
4. Карточка гипотезы: доказательства с переходом к области на листе документа,
   пункт норматива с проверкой актуальности редакции, оценка инспектора.
5. Карта внимания: семь позиций «куда идти на объекте», печать, офлайн-режим.
6. Проект акта проверки в формате DOCX по подтверждённым гипотезам.
7. Журнал аудита: кнопка «Проверить целостность цепочки».
8. Экран администратора: переключение провайдера языковой модели одной строкой
   конфигурации, включение и отключение правил детектора.

## Безопасность

Основная угроза — **инъекция инструкций через проверяемый документ**: документы
предоставляет поднадзорное лицо, заинтересованное в сокрытии нарушений.
Реализованы все семь мер защиты, каждая покрыта тестом. Подробно —
[docs/threat-model.md](docs/threat-model.md).

Проверено автоматически:

- попытка внушения в документе обнаружена и на результат не повлияла;
- запрос к чужому объекту отклоняется на уровне данных, а не интерфейса;
- изменение, удаление и перестановка записей ломают цепочку хэшей журнала аудита;
- тип файла определяется по сигнатуре, обход каталогов невозможен;
- в журналах нет ФИО, токенов и содержимого документов.

## Правовая модель

Система формирует **гипотезы**, а не заключения. Ни одно юридически значимое
действие не совершается автоматически: акт и предписание формируются как проект
и требуют подтверждения инспектором. Уверенность модели отображается всегда и
не округляется до «да / нет».

## Ограничения демонстрационного контура

- Внешние системы, кроме мока СУДИР и мока ИАИС ОГД, представлены заглушками
  за честными интерфейсами. Состояние каждой видно на экране интеграций.
- Тексты пунктов нормативов приведены в кратком изложении и помечены признаком
  `is_paraphrase`. Лицензионный нормативный пакет подключается при внедрении.
- Провайдер языковой модели по умолчанию — офлайн-заглушка. Она реализует тот же
  контракт, что продуктивные адаптеры, и нужна для воспроизводимых тестов.
  Переключение на GigaChat — одна строка в `config/providers.yaml`.
- Все организации и физические лица в демонстрационных данных вымышлены.
