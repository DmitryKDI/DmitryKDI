# CONTEXT.md — текущее состояние «Инспектор ИИ»

## Этап

Сдача конкурсной задачи № 10 строго по ТЗ. Архитектура ТЗ 1.5 реализована:
клиент React, сервер Node.js, ML-модули на Python, RabbitMQ между ними,
кэш разбора в Redis. Запуск — офлайн, `docker compose up -d`; модель только
локальная. Проверка на стенде с GPU — после дедлайна, окна объявят
организаторы.

## Рабочий путь

```text
POST /api/v1/documents/upload (файлы + реестр)              сервер
  -> антивирус, тип по содержимому, лимиты, SHA-256, DWG/DXF -> DXF
  -> очередь inspector.parse                                 RabbitMQ
  -> разбор, OCR, CV, раздел тома; кэш по хешу                ML-воркер, Redis
  -> очередь inspector.inspect (матрица, правила, прошлый протокол)
  -> выбор редакций, сверка по матрице, графика, свободный поиск
  -> inspector.results -> протокол, Checks, Evidence_Fragments  сервер
  -> решения инспектора -> finalize -> JSON / XML / DOCX / PDF -> РиН
```

## Главные файлы

- `packages/server/src/http/routes/` — REST `/api/v1`, схемы = OpenAPI 3.0.3
- `packages/server/src/domain/pipeline.ts` — задачи очереди, повторы, сроки
- `packages/server/src/domain/protocol.ts`, `processes.ts` — статусы, протокол, решения
- `packages/ml/app/worker.py` — задачи разбора и проверки
- `packages/ml/app/official_pipeline.py` — сверка по матрице с доказательствами
- `packages/ml/app/llm.py` — единственная точка обращения к модели, запрет внешней сети

## Постоянные правила

- ТЗ первично; от него не отклоняться.
- Техническая ошибка ≠ «нарушений нет»; не наблюдали ≠ отсутствует.
- Кандидат ≠ нарушение; подтверждает только инспектор.
- Код общий для любой документации; константы объявлены.
- Реальные документы, реквизиты объектов и секреты в git не попадают.
