# CONTEXT.md — читать ПЕРВЫМ в каждой сессии, до CLAUDE.md

Этот файл существует по одной причине: `CLAUDE.md` вырос до 82 пунктов
Приложения Г и 1100+ строк. Прочитать его целиком в начале каждой сессии
нельзя, а читать по диагонали — ровно тот способ, которым уже был потерян
день (Г.76→Г.78: три раунда правок промпта против бага, которого в промпте
не было). Здесь — сжатая карта: где мы, что применимо сейчас, куда не
ходить. **`CLAUDE.md` остаётся источником истины** — этот файл только
говорит, КАКИЕ его пункты открывать.

Порядок чтения: этот файл → `CURRENT-TASK.md` (что прогонять прямо
сейчас) → нужные пункты Г.N из `CLAUDE.md` по карте ниже. Остальное — по
мере надобности, не «на всякий случай».

## 1. Где мы сейчас (этап, а не список задач)

**Этап: извлечение требований и способов производства работ из текста ПД.
Рабочей документации (РД) на этом этапе НЕТ ВООБЩЕ.**

Это главное, что теряется при потере контекста, и главное, что ломало
работу трижды подряд. Всё, что в проекте написано про сравнение ПД↔РД,
триангуляцию, эскалацию в зрение, маршрутизацию — построено, покрыто
тестами, работает, и **сейчас не запускается ни одним прогоном**. Не
чинить, не улучшать, не «заодно проверить»: у этого этапа нет входных
данных.

Что нужно пользователю на выходе: по одному тому за раз — **краткая
сводка требований и способов работ с номерами страниц, шум отсеян
ЛЛМ-фильтром**. Всё.

Приоритет внутри самого извлечения (Г.81/83, прямое указание
пользователя, менять только по новому прямому указанию):

1. **Требования из текста** (форма 3 + ЛЛМ-фильтр) — главный и по
   умолчанию единственный результат.
2. Справка о файле (раздел, число страниц) — контекст, печатается ПОСЛЕ.
3. Требования с привязкой к номеру помещения (форма 1/2) — **выключены
   по умолчанию**, флаг `--with-room-requirements`. Питают сверку с РД по
   номеру, которой нет; стоят десятки вызовов ЛЛМ против пяти у формы 3;
   на разделах, где требования относятся к объекту целиком (ООС, ПОС,
   ПБ), по своей природе дают 0.
4. Реестры помещений/оборудования — **не запускаются вообще**. Счётчики
   «помещений: N» из вывода убраны намеренно (Г.81): они создавали
   ложное впечатление, что регистры помещений — приоритет.

## 2. Почему в инструкции 82 пункта, хотя задача одна

Прямой вопрос пользователя, и ответ на него важен для работы, а не для
истории.

**Пункты Г.N — не проект и не список шагов. Это журнал находок:** каждый
записан ПОСЛЕ того, как что-то реально не сработало на реальных
документах, и объясняет, почему код устроен именно так. Они накопились не
от усложнения замысла, а потому что предметная область (реальные ПД/РД
российского стройнадзора) даёт много независимых способов сломаться,
каждый из которых виден только на живом файле: растровый штамп без
текстового слоя, том без буквенного кода в имени, требование в прозе без
номера помещения, поставщицкий каталог, подшитый внутрь тома.

**Отсюда же и проблема, которую заметил пользователь.** 82 пункта читаются
как один общий пайплайн, и код рос так же — исполняя всё подряд
последовательно. Но программа последовательна: шаг, бесполезный на текущем
этапе, стоящий ПЕРВЫМ, забирает лимит частоты провайдера и время у шага,
ради которого прогон запущен. Именно так КР/НВ упирались в 429 (Г.78), а
форма 1/2 давала «извлечено: 0», сжигая 69 вызовов ЛЛМ против 5 у формы 3
(Г.83). Лечение — не сокращать журнал (находки реальны), а **разделить
пункты по этапам и запускать только пункты текущего этапа**.

Разбивка всех 82 пунктов по этапам:

## 3. Постоянные правила — действуют всегда, независимо от этапа

Это те 8, которые нарушать нельзя ни на каком этапе. Коротко, чтобы не
открывать `CLAUDE.md` ради них:

- **Г.10 — тишина никогда не означает «чисто».** Сорванный вызов, пустой
  результат, пропущенный шаг — печатать явной строкой. Каждая крупная
  потеря времени в этом проекте была молчанием, принятым за результат.
- **Г.11 — не гадать.** Фильтр, порог, правило — только по реально
  наблюдённому выводу, не по ожидаемому. Три раунда правок промпта в
  Г.74/76 были угадыванием вслепую при неработавшей связи.
- **Г.12 — прогресс меряется слепым прогоном** на реальных документах, не
  тем, что тесты зелёные.
- **Г.21 — статус n=1.** Правило, выведенное с одного комплекта, помечать
  как n=1 честно, а не подавать как общий закон.
- **Г.24 — примеры в методике обезличенные**, без референса на объект.
- **Г.25 — чек-лист гарантирует порядок, не глубину.**
- **Г.41 — результат на диск/экран сразу**, по мере готовности, не одним
  куском в конце: прогон может не дожить до конца.
- **Г.42 — целевой аудит на overfitting**: механизм, подогнанный под один
  документ, проверять на том, для чего он не писался.

Плюс правило работы с самим `CLAUDE.md`: **журнал append-only**. Новые
записи Г.N добавляются в конец, прошлые не переписываются — даже когда
позднейшая находка их опровергает (тогда новая запись говорит, что и
почему опровергнуто; так устроены Г.74→76→77→78).

## 4. Грабли, на которые уже наступали — не повторять

- **«ЛЛМ-фильтр не фильтрует» ≠ проблема промпта.** Три раунда ушло на
  правку промпта, пока настоящей причиной была SSL-ошибка сертификата
  GigaChat, молча превращавшая каждый вердикт в «оставить» (Г.77/78).
  Первым делом смотреть строку `ВНИМАНИЕ: N из M кандидатов НЕ получили
  вердикт ЛЛМ вообще` — если она есть, результат недостоверен, и никакие
  выводы о качестве модели по нему делать нельзя.
- **`GIGACHAT_CA_BUNDLE=false` — переменная окружения**, читается
  `llm.py` при импорте. Наличие файла `vision-keys.env` на диске само по
  себе не делает ничего: ни один скрипт не парсит `.env` напрямую.
- **«извлечено: 0» у формы 1/2 — не сбой связи.** Это отброс требований
  без номера помещения (Г.83). На ООС/ПОС/ПБ это норма, а не поломка.
- **У облачной сессии Claude Code нет ключа GigaChat и нет реальных
  документов объекта.** Реальные прогоны делает GigaCode/пользователь
  локально и присылает отчёт. Не притворяться, что прогнал.
- **Г.12 — реальные данные объекта в git не коммитятся.** Тексты
  требований, содержимое PDF, имена реальных файлов — только в чат или в
  файл вне репозитория.

## 5. Карта файлов

- `CLAUDE.md` — источник истины, журнал Г.1–Г.83 (append-only), **только
  короткие правила** — 3-4 строки на запись, всё Приложение Г ≈ 257 строк.
- `docs/PRILOZHENIE-G-ISTORIYA.md` — полный текст тех же Г.N с
  доказательствами, цифрами прогонов и разбором ошибок (2263 строки).
  Открывать точечно, по конкретному номеру, когда короткого правила не
  хватило — не читать подряд. **Правило на будущее: новая запись Г.N
  пишется коротким правилом в `CLAUDE.md` и полным текстом сюда.** Именно
  несоблюдение этого правила на Г.50–Г.83 и раздуло `CLAUDE.md` вдвое.
- `CONTEXT.md` — этот файл, карта для входа в сессию.
- `CURRENT-TASK.md` — что прогонять прямо сейчас; его читает GigaCode.
- `GIGACODE.md` — правила для GigaCode (роль: диагностика, не редактура).
- `packages/backend/` — **реальный движок** (порт 8010). Вся механика
  Приложения Г.
- `packages/api/` + `analysis/` + `llm_core/` — старый демо-движок CRM.
  Не путать: правки требований идут НЕ сюда.
- `scripts/summarize_requirements.py` — **инструмент текущего этапа**:
  требования из текста, без единого шага, зависящего от РД.
- `scripts/registry_diff.py` — полная цепочка со сверкой РД (этап позже).

Ключевые модули текущего этапа:
`app/requirement_registry.py` (форма 3 — regex-каталог),
`app/requirement_llm_filter.py` (ЛЛМ-фильтр шума),
`app/requirement_llm_extract.py` (форма 1/2, по умолчанию выключена),
`app/classification.py` (какой это раздел).

## 6. Как проверять

Полный набор тестов (в этой среде — 396/396):

```
cd nadzor-ai
PYTHONPATH=.:packages/backend python3 -c "import sys,pytest; sys.exit(pytest.console_main())" packages/backend/tests -q
```

Оговорка: это число воспроизводимо только в облачной среде — 6+ тестовых
файлов зашивают абсолютные пути скретчпада сессии и `/home/user/nadzor_sample`
без `skipif` (известно с коммита `0e04aaf`, не сегодняшняя регрессия). На
машине пользователя эти тесты упадут `FileNotFoundError`, а не скипнутся.

Смоук нового инструмента без реального ключа (проверяет структуру вывода
и обработку ошибок, не ответ модели):

```
python3 scripts/summarize_requirements.py --pd "<реальный PDF>" --provider gigachat --api-key FAKE
```
