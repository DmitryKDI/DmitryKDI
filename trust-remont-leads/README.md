# ТРАСТ РЕМОНТ — поиск тёплых лидов

Локальная система поиска тёплых лидов на ремонт квартир (Москва, премиальный сегмент)
для компании ТРАСТ РЕМОНТ. Один Python-проект без n8n и внешних оркестраторов,
рассчитан на запуск в Termux на Android.

## Источники

1. **Telegram** — публичные группы/чаты новостроек (Telethon, MTProto, вход под личным аккаунтом).
2. **ВКонтакте** — группы новостроек и районные паблики (официальный VK API, метод `wall.search`).
3. **Форумы / Q&A о ремонте** — публичные HTML-страницы (`requests` + `BeautifulSoup`).

Avito и Циан сознательно не включены — их пользовательские соглашения прямо запрещают парсинг.

## Законность

Собирается только то, что уже опубликовано в открытых источниках:
- Telegram: только группы, в которые вошёл собственный аккаунт, и только публичные сообщения.
- VK: только официальный API с валидным токеном, без обхода приватности.
- Форумы: только публичные страницы, доступные без авторизации.

Никакого сопоставления с телефонными базами, обхода приватности или парсинга закрытых чатов.

## Структура проекта

```
trust-remont-leads/
├── main.py                # точка входа: запускает все сборщики по очереди
├── telegram_collector.py  # сбор сообщений из Telegram (Telethon)
├── vk_collector.py        # сбор постов из VK (wall.search)
├── forum_collector.py     # сбор сообщений с форумов (requests + bs4)
├── filter.py               # классификация "тёплый лид / не лид"
├── storage.py              # SQLite-дедупликация + запись в CSV/XLSX
├── config.py                # загрузка .env (без внешних зависимостей)
├── keywords.json            # редактируемые триггерные фразы и стоп-слова
├── forum_sources.json       # список форумов и CSS-селекторы для парсинга
├── requirements.txt
├── .env.example              # шаблон конфигурации — скопировать в .env
├── logs/run.log               # лог работы (создаётся автоматически)
├── data/leads.db               # SQLite: история и дедупликация (создаётся автоматически)
└── output/
    ├── leads.csv                # основной результат
    └── leads.xlsx                # тот же результат в Excel (если установлен openpyxl)
```

## Формат `leads.csv` / `leads.xlsx`

| Дата | Источник | Название группы | Автор | Текст сообщения | Ссылка | Совпавшие ключевые слова | Уверенность (0-1) | Статус |
|---|---|---|---|---|---|---|---|---|

Новые лиды дописываются в конец файла. Дубликаты (по хэшу текст+автор) отбрасываются
на уровне SQLite ещё до записи в CSV/XLSX.

## Логика фильтрации

Сообщение — тёплый лид, если:
- найдена хотя бы одна триггерная фраза намерения ("ищу бригаду", "кто делал ремонт", "нужен мастер" и т.п.);
- и НЕ найдено ни одного стоп-слова, характерного для рекламы исполнителя ("делаем ремонты", "бригада отделочников", "недорого сделаем" и т.п.) — при наличии стоп-слова сообщение отбрасывается сразу, независимо от триггеров.

Списки триггеров и стоп-слов редактируются в `keywords.json` без правки кода.
Уверенность растёт с числом совпавших триггерных фраз (0.5 за первую, +0.15 за каждую следующую, максимум 1.0).

## Установка в Termux с нуля

1. Установите **Termux из F-Droid** (не из Google Play — версия в Play Store устарела и не обновляется):
   https://f-droid.org/packages/com.termux/

2. Обновите пакеты и поставьте Python:
   ```bash
   pkg update && pkg upgrade
   pkg install python git
   ```

3. Скачайте проект (например, клонированием репозитория или копированием папки `trust-remont-leads`
   на телефон) и перейдите в неё:
   ```bash
   cd trust-remont-leads
   ```

4. Поставьте зависимости:
   ```bash
   pip install -r requirements.txt
   ```
   Если `openpyxl` по какой-то причине не ставится — не страшно, `main.py` пропустит генерацию
   `.xlsx` с предупреждением в лог, а `leads.csv` всё равно будет создан.

5. Скопируйте шаблон конфигурации и заполните его:
   ```bash
   cp .env.example .env
   nano .env   # или любой другой редактор
   ```

## Настройка Telegram

1. Зайдите на https://my.telegram.org, авторизуйтесь номером телефона.
2. Откройте **API development tools**, создайте приложение (любое название/платформа).
3. Скопируйте `api_id` и `api_hash` в `.env` → `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`.
4. В `TELEGRAM_GROUPS` перечислите публичные группы/чаты через запятую
   (username, ссылка `t.me/...` или инвайт-ссылка) — например:
   ```
   TELEGRAM_GROUPS=zhk_symbol_chat,https://t.me/zhk_novokosino_chat
   ```
5. При первом запуске `python main.py` Telethon попросит ввести номер телефона и код
   подтверждения — введите их прямо в Termux. После этого создастся файл сессии
   (`trust_remont_session.session`), и повторный ввод кода не понадобится.

## Настройка VK

1. Получите токен сообщества (Управление сообществом → Работа с API → Ключи доступа сообщества)
   или токен пользователя с правом `wall` (через Standalone-приложение VK ID).
2. Впишите токен в `.env` → `VK_ACCESS_TOKEN`.
3. В `VK_GROUPS` перечислите домены (короткие имена) пабликов через запятую:
   ```
   VK_GROUPS=zhk_symbol,zhk_novokosino
   ```

## Настройка форумов

Отредактируйте `forum_sources.json` — для каждого форума укажите `url` и CSS-селекторы
для блока сообщения (`message_selector`), автора (`author_selector`, необязательно)
и ссылки на сообщение (`link_selector`, необязательно). В файле уже есть пример с комментарием.

## Первый тестовый прогон (1-2 группы)

Чтобы проверить качество фильтрации перед полноценным запуском:

1. В `.env` оставьте всего 1-2 группы в `TELEGRAM_GROUPS` / `VK_GROUPS`, либо один источник
   в `forum_sources.json`.
2. Убедитесь, что `RUN_MODE=once` (разовый запуск).
3. Запустите:
   ```bash
   python main.py
   ```
4. Проверьте `logs/run.log` — сколько сообщений просмотрено, сколько отфильтровано и почему.
5. Откройте `output/leads.csv` и посмотрите, какие сообщения попали в лиды и какие ключевые
   слова совпали. Если фильтрация слишком строгая/мягкая — правьте `keywords.json` и запускайте
   `python main.py` заново (дубликаты не задвоятся благодаря SQLite).

## Разовый запуск

```bash
python main.py
```

## Запуск в фоне на телефоне

Чтобы скрипт не завершался при сворачивании Termux:

```bash
termux-wake-lock
nohup python main.py > logs/nohup.log 2>&1 &
```

Для непрерывной работы с паузой между проходами (без внешних планировщиков) выставьте
в `.env`:
```
RUN_MODE=loop
RUN_INTERVAL_MINUTES=30
```
и запустите тем же способом через `nohup`. Скрипт сам будет засыпать на `RUN_INTERVAL_MINUTES`
между проходами.

Чтобы скрипт автоматически стартовал при перезагрузке телефона, поставьте
**Termux:Boot** (тоже из F-Droid) и добавьте в `~/.termux/boot/start-leads.sh`:
```bash
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
cd ~/trust-remont-leads
nohup python main.py > logs/nohup.log 2>&1 &
```
и сделайте файл исполняемым: `chmod +x ~/.termux/boot/start-leads.sh`.

## Как посмотреть результат на телефоне

1. Один раз выполните `termux-setup-storage` и разрешите доступ к хранилищу.
2. Результат лежит в `~/trust-remont-leads/output/leads.csv` и `leads.xlsx` внутри Termux.
   Чтобы файл был виден в обычном файловом менеджере, скопируйте его в общее хранилище:
   ```bash
   cp output/leads.xlsx ~/storage/downloads/
   cp output/leads.csv ~/storage/downloads/
   ```
   После этого файл появится в папке "Загрузки" и его можно открыть в Google Таблицах,
   Excel или любом файловом менеджере на телефоне.

## Переменные окружения (`.env`)

См. подробные комментарии в `.env.example`. Кратко:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | ключи с my.telegram.org |
| `TELEGRAM_SESSION_NAME` | имя файла сессии Telethon |
| `TELEGRAM_GROUPS` | список публичных групп/чатов через запятую |
| `TELEGRAM_MESSAGE_LIMIT` | сколько последних сообщений проверять за проход |
| `VK_ACCESS_TOKEN` | токен VK API с правом `wall` |
| `VK_GROUPS` | список доменов пабликов через запятую |
| `VK_SEARCH_COUNT` | сколько постов запрашивать на одну ключевую фразу |
| `FORUM_ENABLED` | включить/выключить сбор с форумов |
| `DB_PATH`, `CSV_PATH`, `XLSX_PATH` | пути к файлам хранения |
| `RUN_MODE` | `once` (разово) или `loop` (бесконечный цикл с паузой) |
| `RUN_INTERVAL_MINUTES` | пауза между проходами в режиме `loop` |

## Логирование

Всё пишется в `logs/run.log`: что собрано по каждому источнику, что отфильтровано и почему,
ошибки API и сети. Уровень `DEBUG` показывает причину отсева каждого отдельного сообщения —
включается через `logging.basicConfig(level=logging.DEBUG, ...)` в `main.py`, если нужно
более подробное журналирование при отладке фильтров.
