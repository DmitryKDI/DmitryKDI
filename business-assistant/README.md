# ИИ-бизнес-ассистент — демо-прототип (MVP)

PWA-скелет для команды ремонтно-строительной компании / компании
строительно-технической экспертизы: чат с ассистентом (function calling
поверх Claude API), дашборд с метриками, раздел «Продажи» с ролевым доступом
и генерация Excel-отчётов. Все данные под капотом — **мок-адаптер**
(тестовый набор из 12 объектов/сделок), архитектура сразу спроектирована под
замену на реальные Битрикс24/LPTracker без переписывания промптов, схем
инструментов и интерфейса.

## Что уже работает (демо-режим)

- **Чат-ассистент** (вкладка «Ассистент») — реальный Claude API с function
  calling: спрашивает/меняет статус сделок, создаёт/удаляет задачи,
  генерирует Excel-отчёт (реальный `.xlsx`, не заглушка) со ссылкой на
  скачивание прямо в чате.
- **Дашборд** — карточки с крупными цифрами (новые заявки, конверсия,
  объекты в работе, открытые задачи), график «объекты по этапам», таблица
  сделок, история звонков (пока мок — LPTracker не подключён).
- **Продажи** — переключатель ролей (демо, без логина): «Начальник отдела
  продаж» видит агрегированную статистику по всем менеджерам (рейтинг по
  сумме закрытых сделок), каждый менеджер — только свои закреплённые
  сделки и контакты клиентов (включая телефоны).
- **PWA**: манифест, установка на экран, офлайн-кэш app shell
  (`vite-plugin-pwa`).
- Голосовой ввод/вывод — placeholder (кнопка микрофона задизейблена,
  подписана «Этап 3»), пока не реализован — см. «Что дальше».

## Кросс-платформенность

Один код — работает и устанавливается как приложение везде, где есть браузер:

- **iOS/Android (телефон/планшет)** — открыть сайт в браузере → «Добавить
  на экран» → работает в полноэкранном режиме, со своей иконкой, без адресной
  строки. Для iOS отдельно подключены `apple-touch-icon` (PNG 180×180) и
  `apple-mobile-web-app-*` мета-теги в `client/index.html` — просто SVG-иконки
  в manifest для iOS недостаточно, Safari её для установки не использует.
- **Android** — манифест содержит и `purpose: "any"`, и `purpose: "maskable"`
  PNG-иконки (192/512), чтобы адаптивная иконка не обрезалась криво под
  разные маски (круг/сквиркл/квадрат у разных производителей).
- **Десктоп (Windows/macOS/Linux)** — обычный браузер или установка как
  приложение через Chrome/Edge («Установить приложение» в адресной строке).
- Раскладка проверена вручную (headless-скриншоты) на 360×780 (маленький
  Android), 390×844 (iPhone), 768×1024 (iPad), альбомной ориентации
  (844×390) и 1440×900 (десктоп) — без горизонтальных переполнений; поля
  ввода ≥16px (иначе Safari на iOS зумит страницу при фокусе); учтён
  `env(safe-area-inset-*)` под чёлку/notch и домашний индикатор.
- Исходники иконок — `client/public/icons/icon.svg` (фавикон) и
  `icon-maskable.svg` (источник для PNG-иконок PWA). Если понадобится
  перегенерировать PNG после смены логотипа — подойдёт любой SVG→PNG
  рендерер (Inkscape, resvg, `npx sharp-cli` и т.п.), в проекте это не
  автоматизировано намеренно, чтобы не тащить в зависимости тяжёлый
  рендер-пайплайн ради разовой операции.

## Архитектура

```
business-assistant/
  server/                  Express API
    data/
      adapter.js            фабрика: mock | bitrix24 (DATA_ADAPTER_MODE)
      mockAdapter.js         реализация поверх mockData.js (демо, in-memory)
      mockData.js             тестовые объекты/сделки/задачи/звонки
      bitrix24Adapter.js      каркас реального провайдера (см. ниже)
      lpTrackerAdapter.js     каркас интеграции звонков (Этап 5, не подключено)
    claude/
      systemPrompt.js        промпт с терминологией ниши
      tools.js                 JSON-схемы function calling + исполнение
      chat.js                   ручной agentic-loop (Claude Messages API)
    reports/excelReport.js   генерация .xlsx (exceljs)
    routes/                  /api/dashboard, /api/chat, /api/sales, /api/reports
  client/                   React PWA (Vite)
    src/components/          Dashboard, SalesPanel, ChatPanel, ...
```

**Единый слой адаптера данных.** Ни ассистент (`tools.js`), ни роуты
дашборда/продаж не обращаются к мок-данным или Битрикс24 напрямую — только
через интерфейс `createDataAdapter()` (см. подробный контракт в
`server/data/adapter.js`). Чтобы перейти с демо на боевые данные, меняется
**только** `DATA_ADAPTER_MODE` и переменные окружения — промпты, схемы
function calling и React-компоненты не трогаются.

## Установка и запуск

```bash
cd business-assistant
npm run install:all        # ставит зависимости в server/ и client/
cp server/.env.example server/.env
# впишите в server/.env как минимум ANTHROPIC_API_KEY
```

**Вариант 1 — быстрый демо-прогон (один порт, без hot reload):**

```bash
npm start        # соберёт client/ и поднимет сервер на http://localhost:4000
```

**Вариант 2 — разработка (два сервера, hot reload):**

```bash
npm run dev       # Express на :4000, Vite dev server на :5173 (проксирует /api)
```

Откройте `http://localhost:5173` (dev) или `http://localhost:4000` (prod-сборка).

## Как подключить реальный Битрикс24

1. В Битрикс24: **Приложения → Разработчикам → Другое → Входящий вебхук**.
   Дайте права на CRM (`crm`) и задачи (`task`).
2. В `server/.env`:
   ```
   DATA_ADAPTER_MODE=bitrix24
   BITRIX24_WEBHOOK_URL=https://<ваш-портал>.bitrix24.ru/rest/<user_id>/<webhook_code>/
   ```
3. Откройте `server/data/bitrix24Adapter.js` — там уже реализованы вызовы
   `crm.deal.list/get/update`, `tasks.task.list/add/delete` в правильном
   формате, но **со местами, помеченными `TODO`**, которые обязательно нужно
   подогнать под ваш портал:
   - `STAGE_ID` — соответствие этапов вашей реальной воронке продаж
     (Настройки → CRM → Воронки продаж);
   - тип работ (ремонт/экспертиза) и телефон клиента — скорее всего, это
     пользовательские поля (`UF_CRM_*`) или требуют `crm.contact.get`;
   - привязка задачи к сделке — поле зависит от настроек портала;
   - `getSalesOverview`/`getManagerContacts` (раздел «Продажи») — сейчас
     каркас с примерным `STAGE_ID: 'WON'`, нужно подставить реальный ID
     финальной стадии и продумать, как безопасно матчить `managerName` из
     UI с `ASSIGNED_BY_ID` в Битрикс24.
4. Логика ассистента, схемы function calling и интерфейс — **не меняются**.

⚠️ Каркас не протестирован на реальном портале — это отправная точка, а не
готовое к продакшену решение. Обязательно проверьте лимиты запросов
Битрикс24 REST API при интеграции.

## Как подключить LPTracker (Этап 5)

Ещё не реализовано в этой сборке — только заготовка интерфейса в
`server/data/lpTrackerAdapter.js` с комментариями, что нужно сделать
(эндпоинты LPTracker, обработка webhook с результатом звонка, запись
результата обратно в Битрикс24). Перед реализацией уточните у LPTracker их
актуальный API и — важно для РФ — правила раскрытия того, что звонок
совершает ИИ, а не оператор.

## Раздел «Продажи» и доступ к персональным данным

В этой сборке **нет реальной авторизации** — переключатель роли в разделе
«Продажи» доверяет клиенту (это нормально только для демо-показа). Прежде
чем давать доступ реальным пользователям:

- Реализовать логин (Telegram/email — см. «Что дальше», Этап 6) и
  привязать роль к серверной сессии/токену, а не к параметру запроса.
- В `server/routes/sales.js` добавить проверку: пользователь с ролью
  «менеджер» может запрашивать `getManagerContacts` **только для самого
  себя** — сейчас эндпоинт отдаёт контакты любого менеджера по имени в
  query-параметре.
- Телефоны клиентов — персональные данные; убедитесь, что доступ
  соответствует применимому законодательству (152-ФЗ и т.п.).

## Известные ограничения демо

- Мок-данные сбрасываются при перезапуске сервера (in-memory, не БД).
- Сгенерированные Excel-отчёты хранятся в `server/generated-reports/` без
  автоочистки — для демо не критично, для продакшена нужна ротация/TTL.
- Без реальных ключей (`ANTHROPIC_API_KEY`) чат вернёт понятную ошибку,
  дашборд и «Продажи» работают полностью (используют только мок-адаптер).
