# AGENTS.md — инструкция для кодового агента

Проект — **«Инспектор ИИ»** (каталог `nadzor-ai/`): конкурсная задача № 10,
сверка проектной (ПД), рабочей (РД) и исполнительной (ИД) документации по
132 параметрам Матрицы контроля. Источник истины — техническое задание;
при любом расхождении побеждает ТЗ, от него не отклоняться.

До первой правки прочитать:

1. `nadzor-ai/CLAUDE.md` — жёсткие правила, архитектура ТЗ 1.5, соответствие
   модулей ТЗ коду, стенд проверки;
2. `nadzor-ai/CONTEXT.md` — текущий этап;
3. `nadzor-ai/docs/ЗАПУСК.md` — развёртывание.

## Коротко

- Клиент React (`nadzor-ai/frontend`), сервер Node.js
  (`nadzor-ai/packages/server`), ML-модули Python (`nadzor-ai/packages/ml`),
  RabbitMQ между ними, кэш разбора в Redis, локальная модель vLLM.
- Система выдаёт **гипотезы, а не заключения**: `CONFIRMED_VIOLATION` ставит
  только инспектор. Техническая ошибка никогда не выдаётся за «нарушений нет».
- Закрытый контур: внешних API нет, модель только локальная.
- Код общий для любой документации; реквизиты объектов, документы и секреты
  в git не попадают.

## Команды (из `nadzor-ai/`)

```bash
make install        # зависимости
make test           # vitest (сервер) + pytest (ML)
make check-generic  # код общий, константы объявлены
make lint           # ruff + tsc
make openapi        # docs/openapi.json
```

## Коммиты

`type: описание` (feat, fix, refactor, docs, test, chore, perf, ci), без
строк соавторства ИИ. Перед коммитом — `make test` и `make check-generic`.
